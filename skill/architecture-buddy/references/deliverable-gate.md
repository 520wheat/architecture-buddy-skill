# 完成门禁（S6）

在宣称「架构设计已完成」之前，逐项自检。任一项失败 → 继续补洞，禁止交卷。

1. 摘要能否让陌生人讲清「解决什么 / 不解决什么」
2. 是否有信任/边界与一条端到端主路径
3. 机制与策略是否分开；策略是否有为何选/不选
4. 是否有失败语义与可测验收句（≥3）
5. 是否有演进切片（现在 / 下一刀 / 明确不做）
6. 正文几乎无内部黑话（M1、入口 B、S0…）
7. **N+1**：下一同类需求时，改动是否主要落在「变化轴」上？写清「该改什么 / 不该改什么」
8. **反例**：写明本抽象**必须拒绝**的语义不同问题（避免把一切塞进同一入口）
9. **能力 vs 复杂度**（一句话自问）：这次是在增加可组合能力，还是只在增加缠绕复杂度？
10. **B6 证据完整性**：B6 必须具体写出变化轴、N+1、反例、可组合能力和复杂度证据；只有标题或口号不通过。
11. **圆桌过程证据**：若预检识别高影响分叉，交付物或伴随记录必须保留提议、用户选择、席位/透镜契约与主持人综合结论；综合结论必须进入正文决策与代价。正文仍应是架构设计，不得变成会议记录。
12. **架构定位**：写明设计对象属于哪一层，以及哪些层适用或不适用；不适用必须有理由。
13. **推导链**：能从问题/目标和场景/流程推导到能力/边界、应用/集成和技术机制/质量属性；非业务系统用核心问题、状态不变量或资源边界替换业务词汇。
14. **系统设计边界**：服务、模块、API、数据库、消息组件或技术栈清单不能单独通过架构门禁；必须说明边界为何这样划分、质量属性如何影响取舍和下一次变化改哪里。
