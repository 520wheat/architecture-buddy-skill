# 设计数据与状态 Prompt

## 何时加载

在 DD3 加载。用于为单元定义字段、约束、所有权、生命周期、状态迁移、不变式、可见性、持久化和并发语义。

## 目标

把数据和状态写到足够细，能直接指导实现和测试，同时不改架构级一致性或所有权。

## 输入

- 已确认的契约和详细设计单元；
- 前一阶段输出的显式 Markdown 块；
- 当前用户的最新回复；
- 只使用已显式写出的事实。

## 执行

1. 先说明为什么现在要定义数据和状态，以及回答后会影响哪一类实现细节。
2. 列出每个单元的字段、约束、所有权、生命周期和状态迁移。
3. 明确哪些字段可见、哪些持久化、哪些只在内存中存在。
4. 为并发、重入、重复提交和部分完成写清语义。
5. 若发现需要改架构级一致性或所有权，标为 `blocked` 并回退。
6. 只提出一个问题，优先问最关键的数据归属或状态迁移歧义。
7. 明确用户确认后的处理方式。

## 输出契约

输出一个数据/状态框架，必须包含以下字段：

```text
状态：draft / blocked
已确认事实：
待确认事实：
已做决定：
受影响文件：
当前问题：<一个问题>？
确认结果：待用户确认 / 已确认 / 需修改 / 触发回退
```

字段和状态必须能支持后续行为与失败设计；如果不能，说明契约还没收敛。

## 不得做

- 不得改写架构级一致性模型；
- 不得把字段细节偷换成所有权决定；
- 不得一次问多个状态问题；
- 不得忽略并发和重复请求；
- 不得依赖隐藏上下文。

## 阻塞处理

如果数据或状态设计会改变架构级 ownership、consistency 或 trust boundary，输出 `blocked` 并回退。若只是字段名或默认值未定，保留 `draft`，写明验证条件和回退路径。
