# 交付物综合 Prompt

## 何时加载

在 DD5 加载。用于把前面阶段的结果综合成可交付的详细设计包：overview、module documents 和 architecture feedback references。

## 目标

把已确认的详细设计整理成一个陌生读者可以继续使用的交付物，并明确哪些内容是已确认、哪些还在待确认。
输出必须先生成 overview，再为每个已确认设计单元生成一个 module 文档，并在 overview 中维护一个可列出多条反馈的 architecture feedback 索引，把每个 architecture feedback 项链接到对应的反馈文档；不得输出 implementation code。

## 输入

- 已确认的范围、单元、契约、数据/状态、行为/失败；
- 前一阶段输出的显式 Markdown 块；
- 当前用户的最新回复；
- 只使用已显式写出的材料。

## 执行

1. 先说明为什么现在要综合交付物，以及回答后会影响哪一份最终文档。
2. 按顺序生成 overview、每个 module 文档、architecture feedback。
3. 在 overview 中生成 architecture feedback 索引；每条反馈必须带编号、标题、影响模块、状态、反馈文档引用。
4. 从 overview 中拉出每个 architecture feedback 项，并为每项建立明确链接或引用。
5. 把确认事实、待确认事实、决策和回退项分别放到对应位置。
6. 每个未解决 pending fact 都必须写出：事实、单阶段默认值、默认原因、验证条件、回退路径、重新打开条件。
7. 如果综合后暴露出跨模块不一致，标为 `blocked` 并回退。
8. 只提出一个问题，优先问交付包顺序、命名或附录取舍中最关键的那个。
9. 明确用户确认后的处理方式。

## 输出契约

输出一个交付物框架，必须包含以下字段：

```text
状态：draft / blocked
已确认事实：
待确认事实：
  - 事实：
  - 单阶段默认值：
  - 默认原因：
  - 验证条件：
  - 回退路径：
  - 重新打开条件：
已做决定：
架构反馈索引：
  - 编号：
  - 标题：
  - 影响模块：
  - 当前状态：
  - 反馈文档引用：
受影响文件：
当前问题：<一个问题>？
确认结果：待用户确认 / 已确认 / 需修改 / 触发回退
```

交付物必须能直接进入 review 阶段；如果不能，说明综合还不完整。

## 不得做

- 不得引入未确认的新内容；
- 不得把 architecture feedback 混进模块正文；
- 不得省略待确认事实的必填字段；
- 不得一次问多个交付包问题；
- 不得依赖隐藏上下文；
- 不得在发现跨模块不一致时继续装作完成。
- 不得输出实现代码、伪代码生成结果或代码块式实现示例。

## 阻塞处理

如果综合后仍有跨模块不一致、缺失证据或架构级缺口，输出 `blocked` 并回退。若只是文档顺序、标题或附录位置未定，保留 `draft`，记录默认值与验证条件。
