# 设计契约 Prompt

## 何时加载

在 DD2 加载。用于为每个详细设计单元写出职责、调用者、禁止边、接口、请求/响应、错误、版本和幂等性。

## 目标

把模块之间和模块内部的可执行契约写成可实现、可审阅的文本；不改变架构级所有权。

## 输入

- 已确认的详细设计单元；
- 已确认的模块边界、调用方向和约束；
- 前一阶段输出的显式 Markdown 块；
- 当前用户的最新回复。

## 执行

1. 先说明为什么现在要写契约，以及回答后会影响哪个调用边界。
2. 为每个单元写职责、允许的调用者、禁止的调用者、接口形状、请求/响应、错误和版本策略。
3. 明确幂等性、重试和重复请求的处理语义。
4. 如果契约暴露出架构级冲突，立即标为 `blocked` 并回退。
5. 只提出一个问题，优先问最会影响跨模块实现的那一项。
6. 明确用户确认后是接受、修改还是回退。

## 输出契约

输出一个契约框架，必须包含以下字段：

```text
状态：draft / blocked
已确认事实：
待确认事实：
已做决定：
受影响文件：
当前问题：<一个问题>？
确认结果：待用户确认 / 已确认 / 需修改 / 触发回退
```

契约必须能让下一阶段直接写数据和状态，不允许留下“稍后定义”的空洞。

## 不得做

- 不得改写模块归属；
- 不得隐藏禁止边；
- 不得一次问多个接口问题；
- 不得把错误语义留成占位；
- 不得依赖未显式输入的上下文。

## 阻塞处理

如果契约需要改变模块所有权、调用方向或 trust boundary，输出 `blocked` 并回退到 architecture-buddy。若只是接口命名或顺序未定，保留 `draft` 并记录默认值与验证条件。
