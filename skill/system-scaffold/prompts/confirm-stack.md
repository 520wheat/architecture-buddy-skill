# confirm-stack

## 何时加载

在 SC2 确认阶段加载：用户已经从推荐中选定方向，准备把技术栈锁定为唯一决策。

## 为什么现在讨论

只有在这里，推荐才能变成锁定决策；这一步是文件创建之前的门禁，确认完成前不得进入实现。

## 输入

- 用户已选方向
- 已确认事实
- 架构约束
- 详细设计约束
- 依赖与运行约束
- 候选技术
- 被拒绝选项

## 执行

1. 将用户选择整理成单一、可执行的技术栈决策。
2. 补齐并固定所有必需字段：语言/版本、框架/版本、核心依赖、依赖管理器、build/test/format/start 命令、部署约束。
3. 明确列出被拒绝的选项与原因。
4. 明确写出：确认是文件创建前的门禁。
5. 只提出一个当前问题；如果信息已足够，则问题应是对最终锁定结果的确认。

## 输出契约

必须输出一个锁定决策，包含：

- 已确认事实
- 未决偏好
- 候选选项
- 取舍
- 用户决策
- 语言/版本
- 框架/版本
- 核心依赖
- 依赖管理器
- build/test/format/start 命令
- 部署约束
- 被拒绝选项
- 下一步动作

锁定决策必须保留上述所有字段，且不得丢失未决偏好、候选选项、取舍或用户决策。

## 不得做

- 不得再引入新的候选方向
- 不得在确认前创建文件
- 不得弱化已确认约束
- 不得省略被拒绝选项
- 不得把确认写成建议

## 阻塞处理

若用户选择与约束冲突，立即说明冲突点，回退到推荐阶段，只保留能解除冲突的最小澄清问题。
