# clarify-stack

## 何时加载

在 SC1 推荐阶段加载：架构与详细设计已给出，但技术栈仍未完全确认，且需要先形成可比较的候选方向。

## 为什么现在讨论

现在需要把质量目标、模块边界、数据/状态约束、失败行为、团队偏好与运维约束，转换成可供用户选择的技术栈方向；此时只能推荐，不能静默选定。

## 输入

- 结构化架构约束
- 详细设计约束
- 模块边界
- 数据与状态约束
- 失败行为约束
- 质量目标
- 团队偏好
- 运维/部署约束
- 已确认事实
- 未决偏好
- 候选技术

## 执行

1. 先校验输入是否足以做推荐。
2. 基于约束推导最多两个具体技术栈方向。
3. 每个方向必须说明：适配原因、代价、被拒绝的替代项、建议的验证命令。
4. 只提出一个当前问题，用于补足最关键的缺口或让用户在两个方向间做选择。
5. 不要把任何方向写成已确认决策。

## 输出契约

必须记录：

- 已确认事实
- 未决偏好
- 候选选项（最多两个）
- 取舍
- 用户决策（若本轮已有）
- 下一步动作

## 不得做

- 不得静默选择技术栈
- 不得创建或修改任何文件
- 不得提出多个当前问题
- 不得跳过代价与被拒绝项
- 不得假定未确认字段

## 阻塞处理

若关键输入缺失或存在冲突，只记录缺口、说明需要确认的字段，并把下一步动作收束到最小的一个澄清问题。
