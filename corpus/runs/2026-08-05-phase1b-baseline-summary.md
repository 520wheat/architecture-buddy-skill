## 主要发现

1. 旧 Kafka/etcd 校准文本的领域内容可以很强，但没有 B6 组合增长证据，硬门禁必须拒绝。这证明结构门禁与语义质量不能合并成一个关键词分数。
2. Agent Runtime 正文具备较高语义质量，但没有圆桌提议、用户选择和综合结论记录；过程质量必须独立扣分。
3. Git 的正文与圆桌记录分文件保存：正文是架构设计，圆桌文件是设计过程证据。二者不能互相替代。
4. 当前四个样本的领域分都高，不能据此宣称架构优秀；优秀还要求硬门禁、五维语义分和人工反关键词复核同时通过。

## 下一轮训练输入

下一轮只应针对重复缺陷修改 `SKILL.md`：

- 输出交付模式必须写出 B6 的具体组合边界，而不是只写标题；
- 识别 agent/workflow、持久化/一致性、逻辑模型/物理优化等高影响分叉时，主持人必须先提议圆桌；
- 用户同意或跳过、透镜契约和主持人综合结论必须进入过程记录；
- 领域金标命中与正文语义质量、圆桌过程质量继续分开评分。
