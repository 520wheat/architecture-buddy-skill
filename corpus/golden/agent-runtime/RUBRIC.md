# RUBRIC — agent-runtime

## 必中机制（≥5）

- **工具循环（plan / act / observe）**：模型在回合内决定下一步；调用工具；把工具结果回注上下文，直至完成条件或停止条件
- **工具作为环境接口（ACI）**：工具结果是环境反馈 / ground truth；工具设计与提示同等重要
- **工作上下文 / 会话边界**：循环内状态（session / messages / scratch）与长期记忆、外部系统真相源可区分，而非「一切塞进无限 prompt」
- **权限与审批闸门**：输入/输出护栏、工具白名单或副作用分级；失败可快速中止，而非事后道歉
- **可观测轨迹（tracing）**：步骤、工具调用、护栏命中与人审决策可回放，支撑评估与事故复盘
- （加分）**HITL / 中断恢复**：任意副作用前可暂停、改状态、再继续；长任务靠 checkpoint / 可恢复工作区，避免昂贵整段重跑

## 必中策略分叉（≥3）

- 复杂度阶梯：单次 LLM（±RAG）/ 预定义工作流 vs 模型主导的自治 agent（默认选最简单够用）
- 编排形态：单 agent 内置循环 vs 图运行时（确定性步骤与 agentic 步骤混布）vs handoff / orchestrator-workers
- 人审策略：副作用工具强制审批 vs 仅高风险抽检 vs 全自治（须写明代价）
- （加分）工具执行：同步进程内 vs 沙箱/异步队列/可恢复工作区；运行时厚度：自管 API 循环 vs Agents SDK 原语 vs 耐久图框架

## 叙事完整性

- 层 A（A1–A8）与层 B（B1–B6）齐全，封面元数据完整；B6 需包含变化轴、N+1、反例及能力/复杂度边界证据
- 主路径可走通：目标 →（可选计划）→ 选工具 → 权限闸 → 执行观察 → 轨迹记录 → 完成/中止/人审恢复
- 硬约束动机（非确定性、延迟成本、副作用不可撤销、需可评可追）在摘要或上下文中可见
- 取舍写清放弃了什么（如默认上最重框架、无护栏自治、把产品模块图当架构）及代价
- 正文保持**问题类语言**；不得把整篇写成某一 IDE/产品的包/屏幕拓扑

## 幻觉黑名单（出现则 FAIL）

- 把本金标写成 Codex / Cursor / 某商业产品的**模块图或功能清单**，而无工具循环与边界机制
- 声称「上了 agent 框架就自动安全 / 无需权限与人审」
- 否认工具结果回注或循环观察，把 agent 说成单次生成即永久正确
- 把预定义工作流与自治 agent 混为一谈且不给出 when/when not
- 声称生产级多步 agent「不需要追踪/轨迹」或「失败只能从头重跑、无法中断恢复」且当作唯一正确模型
- 整段套用微服务/前端组件叙事冒充 agent 运行时，或宣称「只要 prompt 够好就不需要 ACI / 护栏」
