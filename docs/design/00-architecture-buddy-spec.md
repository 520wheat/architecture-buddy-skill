## 1. 产品是什么

面向软件/互联网系统的 **架构共思伙伴 Skill**（Agent Skills 协议）：与用户一起界定问题类，分离机制与策略，共写架构笔记；可选 Top N 对照与架构师透镜圆桌。不替用户做最终架构决策。

| 是 | 不是 |
|----|------|
| 问题类级架构设计伙伴 | 模块拆分/画框专家（图仅附录） |
| 主持 Skill + 可选独立透镜 Skill | 运行时依赖女娲（nuwa） |
| 开箱即用的共思流程 + 压缩参考 | 独立向量知识库 / Web 产品 |

## 2. 身份与协作（ADR-0002）

- 定位：**同事/伙伴**，非领导、非替身名人
- 做架构即学习：按对话推进，关键分叉点明笔记锚点（ADR-0008）
- 构建 skill 的过程本身也是学习与助人（ADR-0007）

## 3. 运行时结构（ADR-0003，形态 B）

```text
Architecture Buddy（主持）
  · 伙伴节奏、A/B/C、内化第一性原理、Top N 问询、笔记/模板、圆桌主持
        │ 按需
        ▼
  Lens Skills（0–N，构建期女娲蒸馏，运行时独立安装）
```

- 仅安装主持即可完成有效共思
- 女娲仅构建期；运行时禁止调用

## 4. 入口、流程、产物（ADR-0004 + §2）

**入口**：A 模糊问题 / B 已有方案 / C 调研抽象 —— 识别后短确认。

**主流程**：

```text
识别 A/B/C → 共抽核心问题 → 界定问题类
  → 问询 Top N（同意才做）
  → 可选圆桌（硬分叉先提议）
  → 共写架构笔记 → 够稳时提议类问题模板
```

**产物**：主=架构笔记；加分=类问题模板。领域首版深耕软件产品，叙事不写死扩展。

## 5. 笔记锚点 M1–M9（§3，ADR-0012）

| M | 名称 |
|---|------|
| M1 | 问题类与边界 |
| M2 | 干系人与关注点 |
| M3 | 约束与假设（含一致性/信任） |
| M4 | ASR / 质量目标 |
| M5 | 机制与策略 |
| M6 | 决策与理由（ADR 段） |
| M7 | 权衡、风险、未决 |
| M8 | 证据与学习痕迹 |
| M9 | 模式词汇层级（GoF 默认细粒度） |

完整骨架见 `03-notes-and-templates.md`。模块图仅附录。

## 6. 圆桌与透镜接口（§4）

| 规则 | 值 |
|------|-----|
| 触发 | 用户要求，或硬分叉时**提议**后经同意 |
| 席数 | 默认 2，上限 3 |
| 主持 | 钉对照点 → 请席 → 并列合成 → 用户拍板 |
| 透镜输出 | Markdown 契约（On point / Heuristics / Risks / Would not / Evidence style） |
| 降级 | 未安装透镜 → 用内建模式词表做无透镜对照 |

## 7. 包布局与构建（§5）

**运行时主持包**：

```text
architecture-buddy/  # ADR-0014 normalized package path
  SKILL.md
  references/     # 自 living 压缩，非全书
  templates/      # 笔记骨架
```

**透镜包**：`architecture-buddy-lens-<shortname>/SKILL.md`（ADR-0014；契约 + 启发式）。

**构建期**：nuwa 蒸馏 FP → 写入主持；蒸馏 2–3 透镜 → 独立包。人名与语料另开构建期 ADR。

## 9. 验收场景（实现对照）

| # | 场景 | 期望 |
|---|------|------|
| V1 | 只装主持；模式 A 模糊问题 | 澄清→问题类→问 Top N→笔记含 M1–M9 骨架 |
| V2 | 模式 B 已有方案 | 审视假设/风险/可替换策略；不擅自定案 |
| V3 | 用户拒绝 Top N | 轻量模式对照或跳过，仍能出笔记 |
| V4 | 硬分叉且用户同意圆桌；已装 2 透镜 | 对照表含共识/冲突；用户选择 |
| V5 | 硬分叉但无透镜 | 提议圆桌后降级到模式词表对照 |
| V6 | 包内检查 | 无 nuwa 运行时调用、无密钥、无「我就是某某」 |

## 10. 明确非目标（v1）

- 不替用户选定唯一架构并宣布定案  
- 不擅自启动耗时 Top N  
- 不做独立 KB 服务 / 自动抓取书单全文  
- 不把 GoF 细粒度模式当作笔记主结构  
- 不在 v1 做圆桌自动投票或加权融合最优解  

## 11. 实现分期（计划阶段细化）

1. **P0**：主持 `SKILL.md` + references/templates（流程与 M1–M9 可跑）  
2. **P1**：圆桌主持段 + 无透镜降级  
3. **P2**：构建期女娲蒸馏 FP 合入 + 2–3 透镜包（可并行于 P0 手工草稿透镜）
