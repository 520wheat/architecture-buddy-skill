# 架构设计语义质量评价体系

本体系用于回答「这是不是一份优秀架构设计」，而不只是「是否命中了若干标题或关键词」。它与结构门禁、领域正确性和圆桌过程分开记录。

## 1. 硬门禁

任一项失败，结论为 `REJECT`，不进入优秀评定：

- 含 A1–A8、B1–B6，且 B6 给出变化轴、N+1、反例、可组合能力与复杂度边界的具体证据。
- 明确设计对象/目标层，并能从问题/目标和场景/流程推导到能力/边界、应用/集成、技术机制和质量属性；不适用的层要说明原因。
- 正文是可供陌生读者使用的设计，而不是会议记录、模块清单或命令列表。
- 没有金标明确列出的领域事实幻觉。
- 设计没有在未完成检查前宣称完成；阻塞事实要标为待验证。

硬门禁是必要条件，不是质量分。标题存在、词语出现或篇幅很长，都不能自动通过语义质量。

## 2. Phase 1B 主评分

五个维度各 `0–4` 分，共 20 个原始分，换算为 `semantic_quality_score = 原始分 × 5`。

| 维度 | 0 | 1 | 2 | 3 | 4 |
|------|---|---|---|---|---|
| 问题类与边界 | 缺失/错类 | 只有目标 | 目标、上下文、非目标基本齐 | 边界能指导方案选择，且说明目标层 | 有反例、信任边界、可验证约束和从问题到机制的推导 |
| 机制与策略分离 | 混为组件清单 | 只列技术名 | 有机制和选项 | 依事实说明选择与排除 | 明确稳定机制、策略替换点及代价 |
| 失败、安全与恢复 | 没有 | 口号式可靠/安全 | 有主要失败态 | 有状态、权限、恢复路径 | 有故障刺激、观察结果、身份边界和残余风险 |
| 演进、N+1 与反例 | 没有 | 只有 roadmap | 有现在/下一刀 | N+1 和反例能约束增长 | 给出可组合边界、复杂度曲线和验证触发条件 |
| 证据、决策理由与质量属性 | 无证据 | 结论无依据 | 事实/待验证有区分 | 证据连接到决策和质量属性 | 有来源、代价、指标/验收、不确定性边界和质量属性后果 |

通过条件：硬门禁通过、总分 `>=80`、任何维度不得低于 `2/4`。

优秀条件：总分 `>=90`、五个维度全部 `>=3/4`、人工复核通过，并确认不是关键词命中。

人工评分必须在阅读正文后填写，不能仅根据自动信号赋分。`architecture-quality-report.sh` 只生成工作表并报告可疑缺口。

## 3. 独立分数

### 领域正确性

每个领域的 `domain_score` 单独维护在 `corpus/golden/<id>/RUBRIC.md` 对照中，至少包括：必须机制、策略分叉、领域证据和幻觉黑名单。领域分高不代表正文架构质量高。

### 圆桌过程质量

`roundtable_score` 不混入正文语义分，检查：

1. 是否识别高影响互斥分叉并主动提议；
2. 用户的同意或跳过是否被记录；
3. 席位是否匹配决策点；
4. 每个透镜是否写出决策点、启发式、风险、不会做什么、证据方式；
5. 主持人是否综合冲突、保留边界并形成结论。

没有高影响分叉时可以记录 `not-needed`；发现高影响分叉却无提议，应记为过程缺陷。

## 4. 反例样本

评价器必须持续保留以下负例，并确认它们不会被结构关键词误判为优秀：

- 只有模块清单，没有主路径、机制、策略和失败语义；
- 只有服务、API、数据库和技术栈，没有问题类、业务/核心场景和架构推导链；
- 只有会议记录，没有稳定的架构结论；
- 有 B6 标题但只有抽象口号，没有变化轴、N+1、反例、能力和复杂度证据；
- 有圆桌席位和发言，但没有主持人综合结论；
- 有结论但没有证据、依据、代价或质量属性验收。

## 5. Baseline 与 adopt

对 Git、Kafka、etcd、Agent Runtime 的 live skill 输出分别记录：

```text
structure_score
semantic_quality_score
domain_score
roundtable_score
human_review
```

先记录真实缺陷，再只根据重复缺陷修改 `SKILL.md`。训练候选必须在 held-out 样本上比较结构分、证据分、架构质量分和人工复核；候选只有在没有关键词投机、且四项均有可解释提升时才 adopt。
