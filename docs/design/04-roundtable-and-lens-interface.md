# Design §4：圆桌与架构师视角 Skill 接口

## Status

**Approved（2026-08-05）** — 依据 ADR-0002/0003/0004；**动态选席见 ADR-0016/0017（2026-08-05 增补）**。

## 目标

在需要取舍对照时，由 Architecture Buddy **主持**，从**透镜库（>3 个世界级架构立场）的已安装子集**中按需挑选 **1–3** 席，产出**并列洞见**，由用户拍板；不把圆桌做成辩论赛、替身决策或固定三人班底。

## 何时启动圆桌

| 触发 | 行为 |
|------|------|
| 用户明确要求多视角 / 点名某架构师 | 启动；确认已安装的视角列表 |
| 共思中出现**硬分叉**（机制已清、策略互斥且影响大） | **提议**圆桌；用户同意再请席 |
| 常规澄清、单一明显策略、用户说不需要 | 不启动 |

默认席数：**2**；用户要加深时到 **3**。超过 3 先问是否收敛问题类（避免噪声）。

## 主持职责（Buddy）

1. **选题**：用一句话钉住本轮对照点（例：「PEP 用 Agent/Gateway 还是 Portal？」）
2. **请席（动态）**：对照 `docs/design/lens-catalog.md`（或包内 `references/lens-catalog.md`）与已安装 `architecture-buddy-lens-*`；按 best-for / not-for 过滤，取**互有张力**的 ≤3 席；**说明为何请这几席**（非固定班底）；用户可换席
3. **并行索取**：每个视角 Skill 只回答对照点，格式见「视角输出契约」
4. **合成**：一张对照表——共识 / 冲突 / 各自适用条件 / 未决问题
5. **交还主权**：明确「你可以选 A/B/混合/先验证 X」；Buddy 可给倾向理由，但标记为建议

## 视角 Skill 不做什么

- 不主持流程、不改入口模式、不擅自开 Top N
- 不伪造「我就是某某本人」；以**蒸馏出的启发式透镜**自称
- 不覆盖用户已锁定的硬约束（可指出张力）

## 视角输出契约（运行时接口）

每个视角 Skill 被调用时应能产出（Markdown 小节即可）：

```text
## Lens: <短名>
### On the decision point
<直接回答对照点，≤10 行>

### Heuristics applied
- <可复查的启发式 2–5 条>

### Risks / what they'd worry about
- …

### Would not do
- <明确不推荐的方向及原因>

### Evidence style
<偏好的证据类型：运行数据 / 论文 / 产品对照 / 组织可行性…>
```

主持合成时不得删冲突；冲突必须可见。

## 请席与 Catalog（ADR-0017）

- 库内立场见 `lens-catalog.md`（首批候选如 raft-cp / dynamo-ap / log-stream / gfs-mr / …）
- 圆桌**当场 ≤3**；库容量**必须 >3**，按需求挑选
- 透镜蒸馏思想与做法（ADR-0016），不蒸馏口吻；不扮演真人
- 安全 / Agent 等若库中暂无专席：主持用已有调研词表（ZTA/ASVS、P9）补位，并记 M8「无专席」

## 与笔记（§3）的衔接

圆桌输出进入架构笔记：

- **M8 证据**：圆桌摘要（谁、对照点、共识/冲突）
- **M5/M7**：采纳或搁置的策略及风险
- **M6**：若用户当场决策 → 写 ADR 段；若未决 → 留在未决

## 失败与降级

| 情况 | 降级 |
|------|------|
| 请求的视角未安装 | 列出已安装；提议用 Buddy 内建模式词表做「无透镜圆桌」或暂停 |
| 视角输出空泛/跑题 | 主持重问一次对照点；仍差则换席或结束圆桌 |
| 用户只要结论不要过程 | 给短对照表 + 一句建议；不强迫阅读长启发式 |

## 非目标

- 不在 v1 做自动投票或「加权融合最优解」
- 不在运行时调用女娲
- 不把圆桌做成固定三人每轮必开

## 默认锁定（无重大分歧不改）

- 硬分叉：**先提议，用户同意再请席**
- 当场席数：默认 **2**，上限 **3**；**库内条目数 >3 且非固定班底**
- 视角输出：Markdown 契约即可（v1 不做强制 JSON 字段）
- 选席须说明理由；用户可换席
