# ADR-0006: 架构产物结构必须来自公开公认的架构设计 canon，而非自创

## Status

Accepted

## Context

Design §3 曾草拟「架构笔记 / 类问题模板」目录。但「架构应包含什么、怎么写」本身就是架构问题：若只凭直觉列标题，会与公开、经考验的架构设计实践脱节，也容易滑向系统设计（模块拆分、容量估算）视角。

本项目已明确（ADR-0001）：目标是**一类问题的解法抽象（机制/策略）**，不是系统设计面试式的组件图。

## Decision

1. **冻结自创目录**：在完成公开 canon 调研并写入设计文档之前，不将 §3 草拟结构定为最终格式。
2. **调研对象**是「架构设计 / Architecture Description & Decision」类公开权威，**不是**「System Design 面试/落地组件选型」类材料。
3. Architecture Buddy 的笔记与模板，应从调研结论中**抽取共性机制**（各 canon 都强调的部分）与**可选策略**（各 canon 的差异写法），再固化为 skill 产物格式。
4. 调研产出本身按本项目方法落盘：`docs/design/` 下的调研笔记 + 后续修订的 §3。

## Consequences

- §3 状态改为 Draft / 待调研驱动修订。
- 构建期可把「架构写作 canon」也视为一类可蒸馏/可对照的知识源（与架构师视角包互补）。
- 避免把 C4/模块图/容量规划当作架构笔记的主结构（它们至多是附录或下游系统设计输入）。
