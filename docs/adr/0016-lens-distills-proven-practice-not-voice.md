# ADR-0016: 透镜蒸馏「经市场验证的思想与做法」，不蒸馏口吻

## Status

Accepted（2026-08-05，用户确认）

## Context

Architecture Buddy 的目标是帮助用户得出**优秀、经得起检验/讨论/实践**的架构设计。  
曾考虑以「名人说话方式」为圆桌透镜；但用户坚持「顶级」标准：

1. 顶尖架构能力体现在**代表性架构设计**上；
2. 该设计须经**市场广泛尝试并认可**；
3. 采用/实践该设计的产品本身应**享誉世界**。

在此标准下，圆桌价值来自这些设计背后的**思想与做法**，而非模仿某人语气。口吻蒸馏既难验证，也与「不扮演真人」冲突，对架构质量帮助有限。

## Decision

1. **透镜内容优先级**：机制假设、适用边界、策略分叉、When not、负面后果、验证方式、运维/演化代价 —— 即「思想 + 做法」。  
2. **明确不做**：以「说话像某某」为成功标准；禁止运行时自称真人。  
3. **选席标准**：按**世界级、已验证的架构立场/谱系**选 2–3 席（可挂代表人物或论文/系统名作索引），不按「好写博客、好模仿」选。  
4. **女娲（构建期）用法**：从公开设计文献/系统架构叙述中抽取可复查的做法启发式；产出物仍是独立 `architecture-buddy-lens-*`，由主持按需请席。  
5. **与主持分工不变**：主持负责问题类与共思流程；透镜负责在硬分叉上提供**已验证立场**的对照，不替用户拍板。

## Consequences

- 修订 ADR-0015 选人逻辑：从「Fowler/Hohpe/Hickey 口吻包」转向「Raft / Dynamo 谱系 / 日志型消息」等立场包（具体短名单另定）。  
- references 中的模式词表仍保留，作为公共语言；透镜提供更强的「这一派会怎么取舍」。  
- 验收侧重：圆桌输出是否含可检验的适用条件与 When not，而非文风像不像某人。
