# ADR-0010: 架构与模式调研必须达到「可学习的覆盖面」，禁止样本点到为止

## Status

Accepted

## Context

路径 C 的首轮校准只各取了少量样本（如 AOSA nginx、arc42 HSC、PoEAA 目录级浏览）。  
这对「验证 M1–M8 方向大致成立」有用，但对「弄清优秀架构设计是什么、并沉淀进可帮助很多人的 skill」远远不够：

- 计算机各领域（分布式、数据库、编译、OS、前端、ML 系统、安全等）的架构洞见不同
- 公认模式文献是一整座图书馆（POSA、GoF、PoEAA、EIP、并发/分布式模式等），不是一篇摘要能代表的

作者明确：造 skill 的过程也是学习过程；点到为止的调研无法支撑这一目标。

## Decision

1. **§3 保持 Draft**，在完成「深调研」前不批准为最终产物格式（首轮校准结论仅作假说）。
2. 建立并执行 **深调研计划**（见 `docs/design/03c-deep-survey-plan.md`），覆盖：
   - 多领域、多份可学习的架构描述 / 决策集
   - 多部公认模式文献的系统阅读（按层级与领域）
3. 深调研以「机制 vs 策略」萃取为产出形式：每读一批，更新共享的机制表、策略/模式词汇表、反模式与写作规范——而不是只堆链接。
4. 首轮 `03b` 样本保留为 **种子与对照**，不当作充分证据。

## Consequences

- 进度变慢，换取 skill 与作者认知的真实厚度（符合 ADR-0007）。
- Architecture Buddy 的笔记格式可能在深调研后大幅修订 M1–M8 细则。
- 需要明确调研分期（领域批次、模式书批次）与「够用可冻结 §3」的退出标准。
