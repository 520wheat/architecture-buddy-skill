# ADR-0017: 多顶级立场透镜库 + 按需挑选 ≤3 席（非固定三席）

## Status

Accepted（2026-08-05，用户确认）

## Context

用户认可圆桌**当场最多三席**的可讨论性，但认为 skill 的高可用不能只依赖固定三个蒸馏对象。  
目标是帮助用户得出经得起检验/讨论/实践的架构：不同问题类需要不同的**已验证架构立场**。固定三席会导致：

- 问题落在三席盲区时，圆桌无效或硬套；
- 无法随调研扩展新的世界级谱系；
- 与 ADR-0016「蒸馏思想与做法」冲突——做法库应可增长。

## Decision

1. **构建期**：蒸馏并维护一个 **Lens Catalog（透镜库）**，条目数 **>3**（目标首版至少 6–8 个世界级架构立场；可继续追加）。每个条目是独立 `architecture-buddy-lens-<shortname>/`，内容按 ADR-0016（思想/做法/When not），不是口吻。  
2. **运行时圆桌**：主持根据**对照点 / 问题类 / 用户约束**，从**已安装**目录中挑选 **最适合的 1–3 席**（默认仍倾向 2，上限 3）。**禁止**写死「永远请 A+B+C」。  
3. **每个透镜必须自带选席元数据**（写入该透镜 `SKILL.md` 文首或 `metadata`）：  
   - `stance`：一句话立场  
   - `best-for`：适合的问题类/分叉类型  
   - `not-for`：明确不适用  
   - `evidence-anchors`：世界级验证落点（系统/论文/产品，可复查）  
   - `conflicts-with`：常与哪些立场对打（可选）  
4. **主持选席算法（v1）**：  
   - 钉对照点 → 用元数据过滤 `not-for` → 按 `best-for` 与对照点匹配打分 → 取 Top ≤3，且尽量选**互有张力**的席（避免三席同质）→ 向用户说明「为何请这几席」→ 用户可换席。  
   - 若已安装透镜 < 需要数：降级为「有的都请 + 模式词表补位」，不假装未安装立场到场。  
5. **Catalog 索引**：仓库内维护 `docs/design/lens-catalog.md`（及可选打进主持包的压缩 `references/lens-catalog.md`），列出 shortname、立场、验证落点、安装状态说明；主持选席时优先读此表 + 已安装目录。  
6. **与 ADR-0003/0015/0016**：形态 B 不变；女娲按**立场条目**批量/增量蒸馏；0015 Accepted 时锁定的是**首批 catalog 名单 + 语料**，不是「终生只有三席」。

## Consequences

- P2 工作量从「蒸 3 个」变为「蒸一批 + 选席逻辑写入主持」。  
- 用户可只安装子集；安装越多，圆桌匹配越好（高可用）。  
- 验收增加：给定对照点，主持能说明选席理由且不超过 3；换问题类时席位组合应变化。
