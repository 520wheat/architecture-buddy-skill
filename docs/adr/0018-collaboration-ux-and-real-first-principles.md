# ADR-0018: 共思体验重做 + 纠正「第一性原理」用法

## Status

Accepted（2026-08-05，用户实战差评后）

## Context

用户实装后反馈：引导像怪问卷、边界题逼用户乱填、所谓「第一性原理」只是结果/约束/优化三列表、不知问题意义、仓库结构难管理。

对照公开定义与女娲（马斯克主题）操作：第一性原理是**识别假设 → 拆到不可再简的基本事实 → 由此重推方案**，对立面是**类比推理**（别人这么做/行业惯例/填空模板）。此前 SKILL 把「三条表单」误称为第一性原理，属错误。

## Decision

1. **第一性原理（架构共思中的操作定义）**  
   - 先列出当前方案里「被当成理所当然」的假设（类比、惯例、现成组件名）。  
   - 再拆到问题本身的基本事实：必须成立的物理/业务/组织/信任事实（可检验）。  
   - 再从这些事实**重新**讨论机制与策略，而不是在旧方案上贴标签。  
   - **禁止**把「结果 / 硬约束表 / 优化变量」三格填空称为第一性原理。

2. **对话体验**  
   - 同伴口吻；每次只推进一个清楚的问题。  
   - **先说明为什么问、答完我们能做什么**。  
   - 禁止默认 A/B/C/D 考试题；禁止「硬/软/不写」矩阵逼用户给不会的分类。  
   - 约束与边界：由 Buddy **根据代码/对话证据起草假设**，用户只需认同/否定/改一句——用户不知道时写「待验证」，不逼填。

3. **笔记 M1–M9**  
   - 仍为交付骨架，但是**对话后沉淀**，不是开场问卷顺序。  
   - 对话中少提 M 编号；写笔记时再映射。

4. **仓库布局**  
   - 可安装物集中到 `skill/`；`docs/` 仅设计与调研；根 README 一张图说清。

## Consequences

- 重写 `skill/architecture-buddy/SKILL.md`。  
- 更新安装路径与校验脚本。  
- 旧「三条填空」行为视为缺陷，不再兼容。
