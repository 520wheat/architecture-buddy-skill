# ADR-0001: 架构设计指「一类问题的解法抽象」

## Status

Accepted

## Context

口语里的「架构设计」常被等同于模块拆分、模块连线等**具体系统结构**。  
本 skill 要辅助的对象不同：它面向的是**一类问题的方法论级解法**，而不是某一个细分产品的模块图。

对市面 Top N 成功产品做研究时：

- **相同处 → 机制**（该类问题里几乎绕不开的结构）
- **不同处 → 策略**（在机制之上的可选项与取舍）

## Decision

Architecture Buddy 中的「架构设计」定义为：

> 针对一类问题，抽象出可复用的机制，并厘清策略选项与取舍理由的方法论产物。

具体系统的模块拆分视为该抽象在某一实例上的**落地投影**，不是本 skill 的主目标。

## Consequences

- 对话与产物优先谈问题类、机制、策略、约束与取舍，而不是一上来画模块图。
- Top N 调研的价值在于为机制/策略抽象提供「已被验证」的样本，而不是抄竞品模块。
- Skill 自身也按「解决一类问题（协作做架构设计）」来设计，不绑死单一细分领域。
