# ADR-0007: 造 skill 即学习；成品要能帮到自己与更多人

## Status

Accepted

## Context

Architecture Buddy 不仅是工具交付，也是作者（及后来的使用者）弄清「什么是优秀的架构设计」的学习与探讨过程。  
若调研与产物格式只求「够用能跑」，会浪费这次把问题想透的机会，也削弱 skill 对他人的长期价值。

## Decision

1. **构建期**：把公开架构设计 canon 与优秀样本的调研做深（采用「A 定骨架 → 样本校准」的轻量 C，必要时扩展 B 的材料），调研过程写入 `docs/`，可复查、可讨论。
2. **运行期**：skill 要真实帮助使用者做出更好的架构判断与产物；同时以伙伴身份**培养做架构的能力**，而不是只吐一份看起来完整的文档。
3. **对外价值**：设计时默认「可被更多人安装使用」——术语、结构、诚实边界要经得起公开审视；与 ADR-0006（产物接地于公开 canon）一致。

## Consequences

- 调研与设计文档本身是学习资产，不只是实现说明书。
- §3 与后续 skill 文案会保留「为什么这样写」的简短依据（指向 canon/样本），便于使用者一起学习。
- 进度上接受比「纯 A 最快可跑」更慢一档，换取可迁移的理解与更强的通用性。
