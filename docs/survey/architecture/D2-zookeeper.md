# ZooKeeper Overview
- 域: D2 分布式协调与集群
- 来源: https://zookeeper.apache.org/doc/current/zookeeperOver.html
- 阶段: Phase 4 · 2026-08-05（书单可换项；与 etcd 对照）

## 问题类
为分布式应用提供**可组合的协调原语**（同步、配置、组成员、命名），避免每应用自研协调。

## 硬约束 / 设计目标
- 简单：共享层次命名空间（类文件系统的 znode）
- 复制：ensemble；多数可用则服务可用
- 有序：全局事务序号支撑高层同步原语
- 高性能：读多写少（约 10:1）场景；数据以内存镜像为主 + 事务日志/快照持久化
- 保证：顺序一致、原子、单一系统映像、可靠、时效有界

## 机制（共性）
1. **小数据协调存储**（非通用大文件存储）
2. **Leader 处理写 + 原子广播协议**；读可走本地副本
3. **Watch**（及永久递归 watch）做变更通知
4. **Ephemeral znode** 绑定会话 → 成员/锁等模式的基础
5. 客户端连单服务器；断线换连

## 策略（与 etcd 对照）
| 维度 | ZooKeeper | etcd（既有笔记） |
|------|-----------|------------------|
| 数据模型 | 层次 znode + watch/ephemeral | KV + 修订/租约/watch（gRPC） |
| 共识叙事 | 自定义原子消息/ Zab 族 | Raft 显式教学材料丰富 |
| API 气质 | 少操作原语，客户端拼高层 | 更偏云原生直接 API |
| 问题类重叠 | 强一致协调元数据 | 同左；策略不同 |

## 显式模式名
- 复制状态机 / 多数派
- 层次命名空间作协调总线
- Watch = 事件通知策略

## 决策与负面后果
- 写需同步全集群 → 写比例高时吞吐掉
- 客户端拼装高层原语：灵活也易用错（会话/临时节点语义）
- 与 etcd 选型常是生态/运维熟悉度，而非「谁更像协调」

## 对写作规范的启示
- D2 对照笔记应先钉**同一问题类**，再比数据模型与通知/租约策略 —— 标准 Top N 模板
