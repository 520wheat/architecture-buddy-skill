# NIST SP 800-207 — Zero Trust Architecture
- 域: D7 安全架构
- 来源: https://csrc.nist.gov/pubs/sp/800/207/final · PDF https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-207.pdf
- 阶段: Phase 1 开篇 + Phase 4 部署模型加深 · 2026-08-05

## 问题类
在「网络位置不再等价于信任」的前提下，为企业资源建立**持续验证、最小权限、面向资源的防护**架构（防突破与横向移动）。

## 硬约束 / 信任假设（M3）
- 不因本地网/资产归属而隐式信任
- 访问决策针对**资源**而非网段
- 主体与设备在会话前均需认证授权；假设网络可能已被攻陷
- 会话期间可持续评估；隐式信任区应尽量小（PDP/PEP 之后）

## 机制（共性）
1. **永不信任、始终验证**的原则集（tenets）
2. 逻辑组件：**Policy Engine (PE) + Policy Administrator (PA) + Policy Enforcement Point (PEP)**  
   - PE：信任算法决策（允许/拒绝/撤销）  
   - PA：按决策建立/拆除主体↔资源通信路径（控制面）  
   - PEP：启用、监视、终止连接（可拆为客户端 agent + 资源侧 gateway，或单一 portal）
3. **控制面 / 数据面分离**：PE/PA↔PEP 走控制面；应用流量走数据面
4. **每请求/会话评估**上下文（身份、设备姿态、威胁情报、CDM 等）
5. **聚焦资源保护**；隐式信任区最小化

## 策略分叉 A：策略驱动方式（§3.1）
| 驱动 | 主锚点 | 适用直觉 | 代价 |
|------|--------|----------|------|
| Enhanced Identity Governance | 主体身份与属性定策略 | 开放网/访客/多 BYOD；云 SaaS | 网络层仍可能被侦察/DoS；需监控 |
| Micro-segmentation | 资源/小组网段 + 网关 PEP | 网关/NGFW/主机 agent 护资源 | PEP 管理与动态重配成本高 |
| Network/SDP 风格 | 应用层安全通道（常 agent/gateway） | 需加密通道与动态准入 | 与身份治理叠加才完整 |

完整 ZT 通常**组合**三种，而非单选。

## 策略分叉 B：部署模型（§3.2）
| 模型 | PEP 形态 | 适用条件 | 关键代价 |
|------|----------|----------|----------|
| **Device Agent / Gateway** | 设备 agent + 资源前 gateway（逻辑一体 PEP） | 可管企业设备；资源前可插 gateway | 无 agent 设备难覆盖；双端运维 |
| **Enclave Gateway** | 网关护一小簇资源（飞地） | 遗留系统难逐个装 agent；相关资源共区 | 飞地内隐式信任更大 |
| **Resource Portal** | 单一门户作门卫（常配合身份驱动） | 云应用/浏览器访问；设备信号次要 | 门户成为枢纽与攻击面 |

一企业内可对**不同工作流**混用多模型。

## 信任算法（§3.3）
PE 综合：身份、资产/请求上下文、威胁情报、资源敏感度等 → 置信度 → 授权结果。变体包括偏静态规则 vs 更连续/风险自适应评分——同一机制下的策略旋钮。

## 显式模式名 / 相邻概念
- PDP/PEP（此处 PDP ≈ PE+PA）
- Least Privilege、Micro-segmentation（策略，非唯一机制）
- 与「城堡护城河」= 明确策略分叉（否定隐式网络信任）

## 决策与负面后果
- 身份与策略基础设施复杂度上升
- 遗留系统需迁移路线；隐式信任区无法立刻为零
- Agent/Portal/Enclave 选择错误 → 覆盖空洞或运维过载

## 对写作规范的启示
- 安全架构：先 **信任假设与威胁**，再逻辑组件，再部署模型表 —— 对齐 M2/M3/M4/M5
- 「逻辑架构 vs 部署模型」是机制/策略分离的标准范本
- Buddy 圆桌涉及时：追问「PEP 放哪、隐式信任区多大、身份是否主驱动」
