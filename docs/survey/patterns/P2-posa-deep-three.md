# POSA Vol.1 深挖三模式：Layers / Pipes and Filters / Broker
- Corpus: P2
- 阶段: Phase 1 · 2026-08-05
- 说明: 基于 POSA1 公开综述与样本对照；非全书逐字摘录

## Layers
- **问题类**：系统可按抽象层次分解，较高层用较低层服务
- **力**：可改性、可测性、团队分工 vs 性能（跨层调用）、层泄漏诱惑
- **后果**：清晰依赖方向；过多层或「穿透调用」会毁掉收益
- **样本**：Berkeley DB 访问方法/缓冲/锁/日志；K8s API→控制器→节点
- **Buddy**：问「层的依赖允许单向吗？有没有泄漏？」

## Pipes and Filters
- **问题类**：流式数据经独立处理步骤变换；步骤可重组
- **力**：灵活性、重用 vs 共享状态困难、错误传播、批/拷贝开销
- **后果**：适合增量协议处理；强共享上下文时别硬套
- **样本**：Envoy Listener/HTTP filter 链
- **Buddy**：问「步骤是否真独立？状态放哪？」

## Broker
- **问题类**：分布式组件需定位、连接、调用对方，而不硬编码位置
- **力**：解耦与位置透明 vs 间接层延迟、经纪成为关键故障域
- **后果**：运维与安全焦点集中到经纪/API 前门
- **样本**：K8s API Server；服务发现；对比 etcd（元数据）≠ 业务经纪
- **Buddy**：问「谁是前门？失败时系统如何降级？」

## 与 Phase1 样本速查
| 模式 | Envoy | K8s | BDB | Caddy |
|------|-------|-----|-----|-------|
| Layers | 部分 | 强 | 强 | Core/Apps |
